# Sentinel final QA — 18 October 2026

Verdict: the installed Ubuntu WSL application is ready for a supervised faculty demonstration as a research prototype. Production protection is not approved by these checks. Use the installed app for the demo; the public download is an older build.

## Issues corrected

1. Completed live sessions were labelled “Recorded replay complete.” The dashboard now distinguishes the modes.
2. A newly started session could retain the previous session’s latest-window counters. The counters now clear until a new complete window arrives.
3. File scans retained at most 50 detection details and also reported that capped length as the total. All detections are now counted, while detail storage stays bounded. The dashboard reports when details are truncated. A 55-detection regression verifies the count.
4. A second privileged collector launch erased the stop request before obtaining the session lock. Cleanup now occurs only after the lock is acquired. An Ubuntu lock regression confirmed a rejected duplicate preserves the request.

All fixes are in the source checkout. The three affected runtime files were also installed into /opt/sentinel, with previous versions backed up in .test-output/installed-before-final-qa. The model was not replaced or retuned.

## Limits that must be explained

A new 22-second harmless process/file/loopback workload flagged 2 of 4 complete windows with the installed adaptation. Collection health passed. This is fresh evidence of false alerts on normal scripted activity, even though replay and saved earlier normal sessions reproduce their previous results. Do not describe the adaptation as eliminating false positives, and do not adjust the cutoff using this QA workload just to make the demo quiet.

Historical 99.19% simulated-window recall and 1.99% normal-window false alarms apply to the retained historical recordings. They are not a fresh general malware-accuracy estimate. Seven aggregate activity features cannot establish malicious intent. WSL observes Linux activity, not Windows applications.

ClamAV peak memory in this check was approximately 999.2 MiB in addition to the app/renderer. Whole-application “ultra-lightweight” claims are unsupported. This scan tests the harmless EICAR integration, not general antivirus efficacy.

Interactive password entry and native popup acknowledgement were not repeated in this automated pass. They were previously human-tested; current Linux authorization logic, in-app alerts, native startup and helper lifecycle passed. Before presenting live mode, manually confirm the Ubuntu authorization prompt and native Test alert once.

A clean-machine installation and broad independent-device/workload validation remain open. The older public archive must not be used to demonstrate the current local app’s newer features. Updating and publishing a new public release is a separate release step; no production-readiness claim follows from this QA.

## Faculty demo — approximately five minutes

1. Start the installed app from Ubuntu with `sentinel`, or from Windows PowerShell with `wsl -d Ubuntu -- /usr/local/bin/sentinel`. If native display support is unavailable, use `sentinel --browser` and keep the terminal open.
2. Open About the model. Confirm “Profile union SVM” and experimental-preview scope; explain the historical metrics and Linux-only monitoring.
3. Return to Overview, select Recorded replay, and start Fast playback. It takes roughly 50 seconds. Expect 600 windows and 253 flagged windows with this installed model. Demonstrate Stop session and restart if useful; a restart begins a new session.
4. Show the activity chart, incident evidence and Incident history. Explain that a flagged window means unusual activity requiring review, not an identified virus.
5. Scan `/home/srinath/Sentinel-Test-Files`. Expect three files scanned, one harmless EICAR test-signature detection and zero skipped files. Do not execute the fixture. Show Test alert and Dismiss.
6. Export report. The notice gives the local JSON and readable HTML paths under the Ubuntu user’s Documents/Sentinel Reports directory. Reports include retained history, so review before sharing.
7. Optional live segment: open System checks, confirm all pass, choose Live Linux monitoring and enter the Ubuntu password yourself in polkit’s authorization prompt. Watch for complete windows, then Stop session. Ordinary activity may cause alerts; explain this limitation. Native password/popup interaction should be manually rehearsed before class.

Use recorded replay as the predictable main demonstration. Do not promise a zero-alert live session or present simulated workloads as real malware.
