BEFORE YOU GO LIVE

System checks

All checks must pass before live monitoring can start. Passing these checks does not verify collector output or event-loss reporting.

Monitoring on Ubuntu / WSL

Live mode observes the Linux environment. It does not monitor Windows applications. The three native CO-RE tools must be installed in /opt/sentinel/collectors.

The desktop stays unprivileged. Linux requests authorization for the fixed collector helper when you start live monitoring. See the included installation guide for collector setup.

Collector failure, reported event loss, or excessive delay stops monitoring and is shown as an error. A stopped monitor does not mean the system is safe.

About the model

A research prototype built on the data already collected.

Normal-window false alarms—Historical normal windows

What these numbers mean

The installed model evaluates process executions, file opens and TCP connections in five-second windows. Its alert cutoff is chosen using separate validation data. Some experimental models also learn from known scripted attack examples.

The reported results come from reserved chronological portions of two previously examined recordings, not independent validation on a new device. New workloads can produce false alarms. WSL testing exposed substantial false alerts in the original model. A local adaptation, when installed, remains an experimental preview and does not establish general malware accuracy.

What Sentinel does

It flags unusual activity for human review and groups consecutive unusual windows into incidents. The separate ClamAV engine scans selected files for antivirus signatures. Behavioral anomalies are not virus identifications. Sentinel does not automatically quarantine files or block processes.

Replay mode

The packaged replay contains 600 reserved feature windows from the existing recordings. They are scored again with the current model. Time gaps reset incident grouping. Replay results are a demonstration, not a new accuracy test.
